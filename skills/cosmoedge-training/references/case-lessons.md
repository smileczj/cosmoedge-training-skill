# 两轮安全帽实践能提供什么参考

需要选用历史办法或解释质量检查的由来时读取本页。以下是 2026 年 9 月两轮公开数据实践的经验摘要，不是当前任务的运行证据，也不是所有检测任务的标准配方。公开叙述见[第一篇实践](https://blog.csdn.net/weixin_48770590/article/details/165489746)和[第二篇实践](https://blog.csdn.net/weixin_48770590/article/details/166104442)。

## 可迁移的判断

| 历史观察 | 当前任务应怎样利用 |
| --- | --- |
| 第一轮跑通了训练、导出和应用展示，未戴帽样本覆盖仍有限 | 分别确认流程能运行和业务效果；先看弱类别及重点场景，不借强类别的指标作结论 |
| 第二轮显著扩大训练数据并改善类别数量比例，最远处极小目标仍缺少 | 同时查看来源、距离、目标像素尺寸和遮挡；达到总量或比例后仍需检查实际缺口 |
| 标注主路径利用来源框、视觉判断与 AI 修订；候选检测器主要用于辅助 | 已有框可复用，按小批质量选择组合；候选框数量不能当作已验收标注数量 |
| 在用户引导下统一测试规则后，模型比较发生明显变化 | 主动检查规则和评价口径；修订要有图像依据，相关模型用相同参考重测 |
| 测试规则修正后，训练与验证数据仍留有旧规则 | 规则变化触发受影响数据和结果检查；只修一份报告不能完成一致性处理 |
| 训练框架与 ONNX 比较通过，应用画面仍出现重复框和坐标差异 | 导出和接入分别验证，继续排查真实输入与后处理，不能用前一项通过代替后一项 |

第二轮的统一测试参考由 AI 复核形成，并保留了未解决疑点。它不能替代独立人工确认或新场景验证。这类事后诊断应保存原结果、修订范围及依据。

## 用过的工具及其适用条件

| 历史选择 | 可以考虑复用的条件 | 需要重新判断的部分 |
| --- | --- | --- |
| YOLOv8n | 常见目标检测、资源受限、已有相容的训练与部署环境；历史选择兼顾成熟度和部署成本 | 目标尺度、精度与速度需求、许可、当前框架和目标解析器是否匹配 |
| Grounding DINO | 需要按文字线索寻找候选位置、补查来源框或发现漏标 | 目标能否被文字区分，实际召回与误框、显存和运行成本；已有标签好时可不用 |
| Qwen3-VL 等视觉模型 | 需要结合图片和规则判断目标属性、解释疑点 | 局部是否看得清、类别误判和输出可靠性；多个 AI 同意不等于标签正确 |
| Label Studio | 需要可视化编辑、人工审阅或结构化导入导出 | 现有工具是否已经足够、类别映射与坐标能否往返一致；不要求每个任务部署 |
| ONNX 与 Mac/x86 CosmoEdge | 希望以现有低成本环境验证模型到应用的连接 | 算子与解析器、真实输出、性能及最终目标设备差异 |

这些工具名称用于定位历史经验。选用前查阅对应工具当前官方文档，检查版本、权重与适用许可，再用当前材料做小批验证。允许沿用、替换或省略；不要为了复现工具组合增加没有必要的步骤。

## 不应搬进通用要求的内容

安全帽案例的图片总数、1∶1 比例、输入尺寸、训练轮数、阈值及机器配置，均是当时任务的选择。迁移时应从新任务重新推导。历史脚本里的固定路径、私有数据、访问凭据和已有缓存不属于 Skill 安装包。

参考经验的价值在于帮助 AI 更早提出正确问题、少遗漏检查。新工具或方法只要符合任务、经过验证并能清楚交付，就可以采用；新任务是否完成仍由本次实际材料、执行与评价决定。
