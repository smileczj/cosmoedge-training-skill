# 按交付范围接入 CosmoEdge

任务包含 CosmoEdge 接入、端到端验证或模型加载失败时读取本页。训练与导出任务不要求提前部署 CosmoEdge。本文按 2026-09-28 核对的仓库内容整理，执行时读取用户所用版本的文档和代码；链接指向官方仓库，分支更新后能力可能变化。

## 先确定目标环境

检查实际实例是否可达、可登录、允许何种操作，以及版本、运行后端、模型管理能力、可用存储和测试数据。已有实例能满足要求时直接利用。缺少实例应提出具体准备方案；继续不依赖它的数据或训练工作，并明确端到端验证正在等待什么。

Mac 上的 Docker 预览是可选开发环境。其可用性、镜像架构、资源和端口要实际检查；Mac/x86 的结果只覆盖该环境。选定设备芯片后，应在相应设备上验证，不能沿用另一后端的运行结论。

可查询官方 [Mac 预览脚本](https://github.com/cosmo-wander-ai/cosmo-edge/blob/main/scripts/macos-docker-preview.sh) 与[模型接入教程](https://github.com/cosmo-wander-ai/cosmo-edge/blob/main/docs/tutorials/05-model-porting/model-porting.md)。先读帮助和版本内容，再选择命令；已有服务不要为套用示例而重建。

## 区分训练导出与产品模型转换

当前 CosmoEdge 正式模型转换执行器从 ONNX 开始；`.pt`、`.pth` 可以作为待评估材料，训练框架导出需要独立检查工程、官方办法和实际输出。一次临时导出成功，不代表 CosmoEdge 已提供通用训练导出服务。

模型格式与目标构建相配：x86 ONNX Runtime 使用 `.onnx`，模型包主文件为 `model.onnx`；Sophon 使用与实际芯片匹配的 `.bmodel`，完整包中的 `model.nn` 还有封装要求，不能通过改扩展名得到。其他后端以当前目标版本的实现为准。

## 让当前模型决定配置

模板提供配置结构和解析器选型的参考。先取得以下事实，再使用模板；已有材料足够时直接读取，不让用户填写技术参数表。

| 事实 | 优先依据 |
| --- | --- |
| 输入输出名称、形状、数据类型、batch、输出布局 | 当前模型的检查工具或目标运行库实际读取结果，绑定模型摘要 |
| 类别 ID、数量、名称及顺序 | 该次训练的数据类别表、权重元数据与导出记录，相互核对 |
| RGB/BGR、归一化、缩放补边、坐标含义、NMS 是否已包含 | 训练/导出及推理实现，结合目标版解析器核对 |
| 文件格式、目标芯片及解析器类型 | 编译产物信息、实际目标构建和对应版本的接入文档 |

模型形状可以帮助核对类别数量，不能自动恢复业务类别名和所有预处理约定。信息冲突时保留两边依据，调查来源；真正缺失且影响运行、结果含义或验收的事实再询问。

用实际值更新模板中的输入输出、输入尺寸、batch 和标签。类别是三类时，不应继承八十类示例的输出声明和标签。标准 YOLOv8、无内置 NMS 的三类模型可能输出 `[1,7,8400]` 或 `[1,8400,7]`；先检查目标解析器是否支持该布局，不能仅因模板不同就转置模型。其他模型按自己的输出含义核对，`640`、`8400`、`类别数 + 4` 都不是通用规则。

需要新解析器或代码变更时，评估代价并按主项目贡献流程处理。保留原模型与配置，修改后的候选单独记录身份。

## 根据材料选择添加或导入

先核对目标版本的页面、接口说明或实现，使用已有产品能力；API 路由和参数以该版本为准。

- **独立模型文件**：目标版本支持时，优先使用“添加模型”。Sophon 上传对应芯片的 `.bmodel`；x86 上传 `.onnx`。正常添加路径可以读取模型信息并生成配置，Sophon 检测模型还会封装为 `model.nn`。生成的默认类别名可能只是占位名，要按训练记录配置实际标签。
- **已有完整模型包**：使用“导入模型”，先检查包结构、配置和内容身份。完整包导入不能假定会重新推断配置或替你封装文件。确需制作包时，使用目标版本支持的封装工具和验证办法。

Sophon 的普通检测 `model.nn` 使用 CENN 容器，包含头和内部 bmodel。检查内部模型内容与源 bmodel 的摘要对应；封装前后整个文件的摘要通常不同。raw bmodel 改名不会生成容器。受保护格式以及其他模型类型按目标版本的加载路径处理，不能统一套 CENN。

可从目标版本的 [添加实现](https://github.com/cosmo-wander-ai/cosmo-edge/blob/main/src/service/model/impl/ModelAddModel.cc)、[配置生成](https://github.com/cosmo-wander-ai/cosmo-edge/blob/main/src/service/model/impl/ModelAddModel_Json.cc)和[完整包导入实现](https://github.com/cosmo-wander-ai/cosmo-edge/blob/main/src/service/model/impl/ModelImporter.cc)核对这些差异。目标环境能力不同或调用失败时，读取返回结果并调查已有替代入口，不从示例拼猜请求。

## 使用主项目已有检查入口

读取目标版本的 [AGENTS.md](https://github.com/cosmo-wander-ai/cosmo-edge/blob/main/AGENTS.md) 和[智能体辅助开发说明](https://github.com/cosmo-wander-ai/cosmo-edge/blob/main/docs/development/agent-assisted-development.md)。涉及其任务模型、远程执行、模型传输、转换或测试设备操作时，按适用要求建立私有任务记录并调用主项目工具；本 Skill 不复制另一套互相矛盾的准入规则。

已明确的操作授权可以直接记录，缺少会影响下一步的授权才询问。密码和 Token 只经受支持的安全输入传递，不进入命令参数、任务文件、日志或发布材料。

常用入口是 `scripts/agent/start.sh`、`connect.sh`、`assess.sh`、`doctor.sh`、`convert_model.sh`、`verify.sh`。按所选路线和当前帮助使用；普通 x86 加载不必套用 Sophon 编译步骤。Sophon 路线需要有效的任务评估、执行环境检查和转换验证，其产物与具体目标芯片绑定。

## 保存后回读，再验证实际用途

1. 回读实际保存的配置和模型身份，核对输入输出、预处理、类别 ID 与顺序、解析器，以及测试任务实际引用的模型。按业务需要核对完整类别或明确选择的子集。请求里的正确值不等于平台已保存正确。
2. 先用固定的正、负、困难图片对照离线结果。存在差异时定位预处理、输出解析或模型问题，保留对照材料。
3. 需要视频应用时，按业务配置检测、区域或时间条件及事件输出；使用[编排教程](https://github.com/cosmo-wander-ai/cosmo-edge/blob/main/docs/tutorials/04-pipeline-orchestration/pipeline-orchestration.md)理解节点用途，实际参数依据当前任务。
4. 检查视频识别、误触发与漏触发，以及任务要求的事件、截图、录像和回放。性能或持续运行要求应在指定负载与时长下测量。

记录模型、应用版本、编排配置、测试材料和实际结果。转换通过只覆盖转换；上传成功只覆盖接收；有画面和事件也不自动表示漏检误报满足要求。报告用普通语言说明各项结果，提供可查看的证据。

## 加载失败时先确定已到达哪一步

从实际日志和目标版代码定位具体报错。错误码可能被多个环节复用，应结合文案、路径和调用位置判断。

| 失败环节 | 优先做的检查 |
| --- | --- |
| 上传、解包或文件定位 | 所用入口、返回值、实际模型路径、文件可读性及模型/任务引用 |
| 容器格式检查 | 文件头、容器版本、各段与文件大小、内部模型身份；核对是否把 raw 模型当成完整封装 |
| BMRT 等运行库加载 | 在已通过前一层的前提下，检查目标芯片、真实加载错误及编译器/运行库兼容证据 |
| 输入输出或解析 | 实际 tensor 与配置、布局、类别、预处理、NMS 及目标解析器支持情况 |
| 图片结果差异 | 同图同阈值对照离线结果，定位颜色、补边、坐标、标签映射及真实误检漏检 |

例如 `model format is not supported` 在某些版本来自 CosmoEdge 文件格式路由，尚未进入 BMRT。应以目标版实现确认位置；只看到新旧工具链年份不同，不足以判断必须重编。已有同一 bmodel 手动成功时，优先比较自动与手动的入口、配置、封装和实际引用；添加入口可能同时修正多项内容，不能只凭成功就把原因归为类别数。

每次修复记录假设、验证办法和实际变化。前一层尚未通过时，调整后处理不能证明修复了加载问题；需要换工具链时先给出支持该方向的证据，保留原产物与已有失败记录。
