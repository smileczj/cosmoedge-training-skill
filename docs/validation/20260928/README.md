## 独立行为检查

每次启动无开发讨论历史的独立 Codex 子 Agent，只提供安装副本和单个任务目录，禁止读取生成器、维护者评分表或其他场景。使用继承的模型和推理设置，没有额外指定；精确模型 ID 未采集。任务只允许运行本地模拟工具并写入独立 `work/`，不联网、安装、训练、转换或访问真实设备。

维护者依据实际模拟工具调用、保存配置、内部载荷摘要和原件摘要复核，结果见 [去除本机路径的检查记录](behavior-evidence.json)。完整本地执行产物不进入安装包。

| 场景 | 修订版结果 | 实际观察 |
| --- | --- | --- |
| 原始模型添加 | 通过 | 两个候选分别添加、回读、模拟加载；三类标签顺序正确，BCN `[1,7,8400]` 与 BNC `[1,8400,7]` 各自保留，没有为模板转置模型 |
| 完整包导入 | 通过 | 使用 import 并回读，保持五类、320 输入和 `[1,2100,9]` 输出；未把车辆案例参数套入包中 |
| 格式失败诊断 | 通过 | 比较同源内部内容，定位模拟容器失败；通过两个单因素对照区分类别配置问题，使用 add 创建新条目并回读、模拟加载，保留原记录 |

原始模型添加场景同时测试旧版。旧版与修订版均完成两个候选的添加、回读、模拟加载和身份核对；原材料摘要均未改变。因此本次没有观察到该场景的关键遗漏从失败变为通过，不能据此宣称成功率提升或远端故障已经修复。

完整包场景的包配置没有保存训练记录中的置信度和 NMS 阈值。受测 Agent 记录了这一边界，没有把模拟加载通过解释为真实推理参数已验证。

格式诊断场景中，只修配置仍在容器层失败；只修封装则进入配置层并失败；完整修复后模拟加载通过。新任务引用是独立的本地派生记录，没有切换真实运行任务。这些结果只解释合成场景，不据此断定任何远端故障的唯一原因。

这些材料及模型服务均为程序合成。模拟封装前缀不是实际 CENN；本次没有运行 BMRT，没有真实图片预测、模型精度、设备性能或持续运行结论。

## 给同事的复核方法

1. 从仓库默认 `main` 安装完整 Skill，记录所用提交。已有同名安装时先备份旧目录，按助手支持的方式替换并开启新会话；本仓库安装器会拒绝直接覆盖已有目录。
2. 沿用任务已授权的开发与测试环境，准备同一份待验模型、训练类别顺序、目标版本和已成功的手动条目。原始文件与成功条目保留，新增独立测试条目。
3. 让新会话自行读取模型信息，选择添加或导入入口，保存后回读配置及模型身份。检查任务是否真正引用了新条目。
4. 使用固定正样本、负样本和困难图片对照离线与应用结果，记录每一类的差异；若加载失败，保留完整阶段日志与配置，不仅截取错误码。
5. 交回所用 Skill 提交、模型摘要、目标版本、实际配置、操作记录、图片结果及未完成项。训练成功、上传成功与设备验收分别报告。

仓库历史预览版附件保持不变；本次尚未创建新 release。真实设备复核由使用方后续执行。
