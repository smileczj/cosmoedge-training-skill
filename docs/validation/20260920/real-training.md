# 辅助训练 Skill 真实执行验证：2026-09-20

本次从已有公开材料出发，完成了新一轮真实训练、检查点恢复、逐类测试和 ONNX 输出核对。候选模型与4张真实输入已交给另一个执行环节做 CosmoEdge 验证。本报告只说明训练与导出部分。

## 为什么这样安排

目标是验证 AI 能按 Skill 判断条件、利用材料、主动检查和处理问题。已有扩展数据包含多个来源，历史验收发现过框选规则遗留，因此本轮选择单一 Hardhat 来源，使用已有标签，没有重复启动预标注。选择已有 COCO 预训练 YOLOv8n，是因为当前环境和后续640输入的部署路线均已支持，不把它规定为其他任务的默认模型。

[Hardhat 原始来源](https://dataverse.harvard.edu/dataset.xhtml?persistentId=doi:10.7910/DVN/7CBGOS)由 Liangbin Xie 发布。复用了此前保存的 CC0-1.0 许可与下载身份记录，见 [数据来源记录](public-source.json)。本次不向公开仓库提交原图、数据集或模型文件。

## 实际执行

- 训练机器具备 RTX 3080 Ti Laptop 16GB；任务启动时约7.5GB显存可用。使用现有 Python 3.10.12、PyTorch 2.12.0+cu126、Ultralytics 8.4.147、ONNX 1.21.0、ONNX Runtime 1.23.2。实际 CUDA 前向、反向和有限梯度检查通过。
- 按既有分组抽取384张训练候选、64张验证和64张测试。检查了选中图片与标签的SHA、坐标格式、文件与像素重复、分组交叉。
- 看12张训练整图时发现1张边缘局部头部疑似漏标，将该整图留出，正式训练383张：helmet 677框、no_helmet 504框。旧任务和原数据未修改。
- 从原始预训练权重训练6轮，640输入、batch8、AdamW、学习率0.001；观察到的训练显存约2.35GB。参数仅服务此次小规模执行验证。
- 第2轮检查点保存后主动结束训练子进程，检查点中epoch和优化器状态均存在，随后从第3轮恢复到第6轮。原始训练日志和6轮结果保留，没有重新从头训练。模型训练计算本身约21秒，恢复启动、评估和导出另计；不作为普遍耗时承诺。

## 发现问题后如何处理

1. **报告保存失败。**原生评价返回的 NumPy int64 不能直接写JSON。修复标量转换后，只重新执行评价与导出，保留初次报错，不重复训练。
2. **导出比对的单位不一致。**对整个输出张量使用同一 `allclose` 容差时，1张图的8个y坐标未通过；输出同时含像素坐标和概率。保留初检报告，分别测量未融合PyTorch、融合PyTorch与ONNX，改用有物理含义的检查：坐标绝对差不超过0.01输入像素、概率差不超过0.00001，并检查后处理数量、类别和框。最大实际坐标差0.004272像素、概率差0.000002176，16张图均通过，模型没有改变。
3. **评价预处理应与应用比较明确对应。**原生AP采用框架的验证设置；用于具体错误计数的另一路预测原先使用自动矩形补边。为与固定640 ONNX应用对照一致，显式改为640×640补边并重算该路计数，原结果保留。
4. **已有分组漏掉了近重复。**进一步按感知哈希搜索测试图的训练集近邻并看图，确认 `test-040` 与 `train-136` 是同一场景近重复，原有分组未将其合并。保留原64图结果，将该测试图留出，使用同一模型在63图上重算。验证集的最近8组候选也经过看图，未在这些候选中确认近重复；这不证明全部拍摄场景都独立。

近重复搜索方法见 [案例近重复候选脚本](near_duplicate_candidates.py)：32×32灰度图、低频DCT的63位感知哈希，计算跨集合距离，生成候选后由AI看图。哈希仅用于找候选，不能仅凭距离判定同场景。

## 修订后的63图结果

下表是排除已确认近重复后的同来源诊断结果。标签来自原数据与已有AI检查，并非独立人工金标准；材料此前用于旧项目，不是新收集的外部盲测。

| 类别 | 参考框数 | 原生AP50 | 原生AP50-95 | 固定阈值TP / FP / FN |
|---|---:|---:|---:|---:|
| helmet | 111 | 0.98176 | 0.68433 | 108 / 14 / 3 |
| no_helmet | 90 | 0.99000 | 0.71145 | 89 / 10 / 1 |

AP使用 Ultralytics 原生 DetectionValidator：confidence=0.001、NMS IoU=0.7。错误计数使用固定640输入、confidence=0.25、NMS IoU=0.45、匹配IoU=0.5，所以不能将表中两种评价当作同一个工作点。TP表示正确检出，FP表示误检，FN表示漏检。

原64图的AP50为0.985934、AP50-95为0.699336；排除1图后分别为0.985883、0.697892。排除是因为实际画面近重复，不是因为模型预测好坏。

实际错误样例仍显示：桌上没有佩戴的安全帽被检出、低头侧身和前后重叠的人头漏检、个别类别混淆。高AP不能据此推出现场达标。下一轮若追求业务效果，应优先增加未佩戴安全帽、遮挡和姿态困难样本，并建立有拍摄场景身份的评价材料。

## 补充：真实 SSH 断开与接手续读

本次另外启动了一次任务私有的后台 ONNX 输出复核。启动后控制 SSH 实际执行退出，工具返回连接已关闭；随后通过新的 SSH 会话读取原作业记录，没有启动第二份作业。后台进程在断开后完成4张真实图片的推理，检出数量分别为9、5、6、5，与保存的 PyTorch 参考框在约定容差内一致，退出码为0。模型、输入数据和参考结果均未修改。

作业使用现有 Python 的 `subprocess.Popen(start_new_session=True)`，输入输出与终端分离，保存作业编号、PID、状态、日志、结果SHA和退出码。启动前安排的30秒等待只用于确保SSH断开窗口，单独记录，不计入训练或推理耗时。远端记录显示05:00:29开始计算、05:00:31完成，新连接05:00:36读到完成状态（UTC）。两台机器的系统时钟约有7分40秒差异，因此没有用跨机器时间计算耗时。

本项验证范围是：后台计算能够跨SSH断开继续，后续会话能按原作业身份读取已完成结果；不表示关闭AI宿主后它仍会持续进行判断与分析。详细记录见 [SSH 断开验证记录](ssh-disconnect.json)。
