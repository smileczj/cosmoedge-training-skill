# CosmoEdge 应用验证

本次将新训练的 ONNX 导入本机 Mac 上独立的 Linux x86 Docker 实例，完成图片识别、视频编排、事件图片与录像检查。原有两个案例实例没有改动。本轮没有设备芯片测试或现场验收。

## 模型与图片

候选 ONNX SHA256 为 `23df0fafd2276226ee1f74e67f7330ca1abdfda9dc2ac3f47cf96437a53ec862`。实际导入后重新读取模型配置，核对输入 `[1,3,640,640]`、输出 `[1,6,8400]`、两类顺序、RGB/255、补边114、confidence=0.25、NMS IoU=0.45。

4张真实图片共返回25个检测框，逐图数量和类别与离线 PyTorch 对应。按类别和位置配对，最大框坐标差1.394原图像素，最大分数差0.006664。实际输出图也经过查看。这里是应用输出的有限样例对照，不是逐元素完全一致；具体预处理差异的根因尚未单独隔离。

其中一张室内图能看到模型将桌上未佩戴的安全帽检出，这一结果延续了训练报告中的业务问题。导入成功与业务效果判断分别记录。

## 视频、编排与事件

使用工程安全帽视频，SHA256为 `ec77182a264f3059a091b68c4973942dba3b80e93f20feaf4d7e146885caf9d2`。编排读取当前实例的节点定义，连接检测、未戴帽目标筛选、条件判断、持续时间和事件输出；模型及编排配置均保存后读回。

本次观察取得1条该通道、该编排的新事件。取回整图、目标截图和事件录像，查看整图与截图，事件目标是画面中未佩戴安全帽的人头。事件录像完整解码72帧，返回码0；实时输出捕获文件完整解码162帧。任务停止后重新读取，启用状态为0。

检查还保留了两个需要区分的现象：

- 实时抓流器在有限视频结束后等待数据超时，保存文件仍能解码；原始超时记录保留，不能描述为全程无错误的抓流。
- 事件录像解码时出现时间戳不单调警告，返回码0且帧可解码。本次没有验证浏览器播放行为，也没有修复这一产品媒体问题。

因此本次支持“候选模型在指定预览环境完成识别、编排、事件和可解码录像输出”。没有用单条事件宣称完整视频召回率、录像兼容性或业务达标。

环境身份、逐图差异和媒体检查数值见 [机器可读记录](cosmoedge.json)。原始图片、视频、完整API记录和模型保存在本次私有工作目录，公开仓库不再分发。
